# `007 lab`: what a lower effort saves and risks in your repository

`007 lab` replays your own commits at two efforts, without a screen, with any agent and any test runner. The source repository is only read.

```bash
007 lab mine --config lab.json --out lab
007 lab sensitivity --set lab/replay-set.json
007 lab feasibility --set lab/replay-set.json --sd 0.23
007 lab run --set lab/replay-set.json --out results --replicates 3 --max-calls 144 --max-usd 150
007 lab report --set lab/replay-set.json --results results
```

Start from [`examples/lab.example.json`](../examples/lab.example.json). Only `run` calls a model. It dispatches a cell only while the spend so far plus a `--stop-usd` reserve for each cell in flight stays under `--max-usd`; a cell that costs more than its reserve can push the total past `--max-usd`, so set `--stop-usd` at or above the costliest expected attempt. It stops when a valid cell reports no cost, on a cell above `--stop-usd` (unless `--over-limit record`), and once `--max-invalid` cells (default 3) are invalid; an invalid cell without a cost is charged its `--stop-usd` reserve. It resumes finished work and never retries a cell (a call the provider refused is dispatched again only with `--requeue-refused`); a cell whose controller raises (a refused snapshot, a crash) is recorded invalid as `controller-error:<type>` instead of ending the run. Before its first dispatch it seals `run-manifest.json` in `--out`: the set (arms and their order, agent command, tasks with their prompts, bases and oracle hashes), the agent command's program (its first word, through `PATH`) and the absolute files it names, also as `--flag=/file`, `KEY=/file`, `--flag=key=/file`, `-f/file`, `@/file` or `--flag=@/file` (through symlinks), this 007, the Python version, and the grading toolchain (`toolchain`: path and version of the interpreter each acceptance command starts and of `go`, `node` or `pytest` when a task's adapter calls them, found on the acceptance `PATH`); every dispatch in `dispatch.jsonl` names that manifest's digest. Each time the run starts or resumes it checks them: anything changed stops it with `manifest-mismatch`, naming what changed; restoring it makes the run resumable. A manifest that is unreadable, or missing after a dispatch named it, stops it with `manifest-unreadable` or `manifest-missing`; only a directory whose dispatches name no manifest (one from before 1.8) is sealed late. A relative path in the agent command resolves inside the task's workspace, which the set's base commit fixes; a later `PATH` lookup (`env agent`) and anything the program launches, environment variables, the CLI's own configuration files, the parts the set lists in `unsealed_files` (name there, before the first dispatch, any absolute file the attempts themselves rewrite, such as a log: otherwise it is sealed and its change stops the run, and a sealed run cannot adopt the list later because it changes the set), and anything else the oracle calls are not sealed; `report` names the sealed files and says when the program itself was not. The manifest guards against accidents, not tampering, and it records absolute paths: check it before publishing a results directory. At a planned pause (`call-budget`, `rate-limit`, `machine-busy` or `quota-hold`), `--replicates`, `--max-calls`, `--max-usd`, `--jobs` and `--max-invalid` can change: raising `--max-usd`, `--max-calls`, `--replicates` or `--max-invalid` is safe; raising `--jobs` reserves more `--stop-usd` at once and can bring a final `usd-budget` sooner; lowering `--stop-usd` below an earlier cell's cost ends the run; limits are not recorded. A provider rate limit with no usage reported (Codex's error event; since 1.9.0 also Claude's "usage limit reached" result and a rejected `rate_limit_event`; a zero-filled usage counts as none) pauses the run (`rate-limit`): the refused cell is charged like any invalid cell (its receipt cost, else the reserve), does not count toward `--max-invalid` and is labelled `provider-rate-limit`; by default it is not retried, and with `--requeue-refused` its files move to `refused/` and it is dispatched again after the pause. A resume within 10 minutes of the newest refusal stops with `rate-limit-cooldown`. Refused calls consume `--max-calls`, and a limit can hit one arm more than the other: `run` returns `refused_per_arm`, and `arm_accounting` and `report.md` count refusals per arm. A budget or invalid stop (`STOP.json`) is final. A manifest stop is not, except `unbound-dispatches` and `unbound-cells`: restoring inputs cannot rebind attempts the seal never covered. An absolute file in the agent command that cannot be read stops the run with `executable-unreadable`; list it in `unsealed_files` before the first dispatch. `--stop-usd` reprices the reserve charged to earlier invalid cells without a cost, and `timeout_s` (Python API) is not sealed. The set's `compare` block is not sealed: a change is reported in `run_manifest` and in the printed verdict (`compare_changed_after_seal`), and it breaks the declared-margin rule below, so it serves an exploratory reading only. `chain` refuses a `compare` moved since stage 1 was sealed (its reference picks stage 2's arm), and refuses to overwrite a different chain set in its directory: its commits are not date-pinned, so `chain` runs once per directory, and a stage 1 topped up later needs a new chain directory and a new stage 2. Mining more tasks after a pilot changes the set, so a sealed pilot directory cannot be extended. `feasibility`, `sufficiency` and the task files `report` reads (`hidden.json`, `baseline.json`, `sensitivity.json`) are not checked against the seal. Dispatches after the seal that do not name it (a 1.7.0 controller), or results no sealed dispatch produced (cells copied in, a lost ledger), stop a resume and report the run as `unbound`. The four states are `sealed`, `sealed-late`, `unbound` and `absent`; the printed verdict carries `run_binding`, and `report.json` names the sealed files and the `unsealed_files` (absolute paths: check before publishing). `report` and `chain` refuse results sealed with another set or under another manifest, or a sealed run whose ledger cannot be read; `report` names the binding in `run_manifest` (`sealed`, `sealed-late`, `unbound` or `absent`) and says if the comparison or margin changed after the seal. With `--next-results` it requires stage 2 to be chained from this sealed run at the reference arm, with the same agent command, and bound to its own seal under the same rules (an `unbound` stage 2 is refused), publishes `next_run_manifest` with how many stage-1 attempts have a stage-2 attempt (a stage 1 topped up after `chain` leaves the new ones without), and refuses a stage 2 older than stage 1's seal, or one that lost the manifest its ledger names (over an unsealed stage 1 there is no seal to chain from, so stage 2's chain is not checked); the printed verdict carries `next_run_binding`. `chain` refuses an `unbound` stage 1. The report's `arm_accounting` gives, per arm, the fate of every planned cell (every task at the most replicates any attempted or finished cell reached): never dispatched, attempted without a result (a dispatch or receipt with no result), invalid by `failure_class`, valid and accepted, with `history` saying whether the dispatch ledger was complete, partial (some results have no dispatch row), absent, damaged or unreadable (without a complete one, a dispatch that left no receipt counts as never dispatched). `report` leaves invalid cells out and names them in `excluded_invalid`; a cell whose test report cannot be read counts as no test passing and is named in `unreadable_outcomes`. `mine` skips a commit with more hidden tests than the acceptance reader takes: 1,999, since the reader's 2,000 outcomes include `__module__`.

- **Agents** are an argv template (`agent_command`) that writes a runner receipt.
- **Tests** are an adapter: `node`, `pytest`, `unittest`, `go`, or `custom`, whose command writes `{test id: pass|fail|skip}` to `$LAB_RAW_REPORT`. With `go`, the agent's own `*_test.go` files go back to base before grading, so a test name it redeclares cannot break a package. A test whose `unittest` class or module, or whose `go` package, fails outside any test (a teardown error, `TestMain`'s exit, a panic after the test returned) reads `error`, not `pass`; a test that fails on its own owns its package's failure, so a test already red at base stays outside the grade.
- **Parallelism** shortens the run; the budget reserves `--stop-usd` for each cell in flight. The default `--jobs` is a quarter of the cores, at least 2; above it every command warns (load moves grades and once restarted a machine), and `--strict-jobs` refuses.

## Running a study unattended

Study F ran Claude Opus 5.5 through `007 lab` 1.8.1 wrapped in scripts. Since 1.9.0 `run` and `report` do that work; every option is off by default, so a run without them behaves as in 1.8.1.

| Option | What it does |
|---|---|
| `--chunk N` | dispatch at most N cells, wait for all of them, run the gates below, then the next chunk |
| `--max-load L`, `--load-wait-s S` | before each chunk, wait (up to S seconds, default 3,600) for the 5-minute load to fall under L, else pause with `machine-busy`; `load.log` records the load every minute and at each gate |
| `--quota-gate` | (the set's `quota_probe` is checked before the seal) before each chunk, run the set's `quota_probe` (`{"command": [argv], "windows": ["seven_day"], "need": 0.6, "ceiling": 0.95}`: one minimal call on the study's model that prints Claude's `rate_limit_event` rows) and pause with `quota-hold` unless every event and window is allowed, no unknown window appears, and each watched window has room: used + need × share of cells left ≤ ceiling. No event fails closed. `quota.jsonl` records each decision and the probe's own cost, which joins `spent` (on resume too); a probe without a measured cost is counted in `quota_probes_unmeasured` and charged the `--stop-usd` reserve, and no probe runs without room for that reserve under `--max-usd` |
| `--cost-marker-at N`, `--cost-marker-hold-usd X` | once, after exactly the first N cells, project the cost (mean per arm × planned cells of the arm; a cell without a cost at the reserve): above X, or with an arm that has no cell yet, `HOLD.json` stops the run for good; else `MARKER.json`, never read again |
| `--requeue-refused` | a refused call is set aside under `refused/` and dispatched again after the pause. A set-aside cell is dispatched again on any later resume, with or without the option; until then `arm_accounting` counts it as attempted without a result. A stream rejected before any result is labelled refused even if the agent had worked, and is charged its reserve |
| `--rate-limit-wait-s S` | wait out `rate-limit` pauses inside the run, 10 minutes at a time, up to S seconds in all; it needs `--requeue-refused`, since without it every refused cell of a long outage would be lost |
| `--over-limit record` | a cell above `--stop-usd` is counted (`over_limit_cells`) and the run goes on; only `--max-usd` stops it. Without it, such a cell ends the run even if a pause was set in the same pass |
| `report --single-look` | refuses while a run holds the results' lock, then writes `LOOK.json` with the report's digest: after it, `report` refuses to read these results again and `run` refuses to add to them (`looked`; a run also checks for `LOOK.json` between chunks, though a run holds the lock that `--single-look` needs, so that check only meets a `LOOK.json` written by other means). Plain `report` calls before it leave no trace, so `LOOK.json` shows the look was taken, not that it was the first |
| `report --missing-data-guard --reserve-usd X --replicates N` | adds `missing_data_guard`; N is the run's `--replicates`, which fixes the plan (the run does not record it; fewer than the cells reached is refused): readings P (valid cells) and B (pairs with both arms), the worse deciding; L2 imputes every planned cell without a usable result as the worst case for the candidate arm (it fails every reachable test, the reference passes every one), and PROVEN needs L0 and L2 both PROVEN in P and B (otherwise NOT-PROVEN, "not decisive by missing data"); the cost per accepted change at the candidate over the reference, with a task-bootstrap interval and a worst case (no cost at X for the candidate and 0 for the reference, an invalid reference cell counted accepted); answer PAYS, PROVEN-NOT-ECONOMIC, DOES-NOT-PAY or the verdict. `compare.critical_floor` in the set sets a floor for the guard's critical value only (the main verdict ignores it, so the two can differ). Without `--frozen-reach`, a task with no valid cell has no reach, so L2 imputes nothing for it. The serial re-grade and A/A are not part of it |
| `report --frozen-reach FILE` | `{task: [tests]}` fixed before the attempts replaces the reach the run's own cells give. The report records the digest of its canonical JSON (`frozen_reach_sha256`, sorted keys: not the file's own hash); it is not sealed |

Validated on published results: on the 2026-11-07 Claude go-json run the guard reproduces L0 4.666643 (critical values 2.2315 and 2.2367), L2 4.0385 and R 0.300 (0.267 to 0.344); its own simulated L2 critical value, 2.2014, equals the one study F's hashed analysis script gives. On study F it reproduces every statistic, critical value and cost ratio of `f-result.json`.

A rate-limit cooldown applies only while planned cells remain. A driver that re-runs `run` in a loop should still cap its own retries: a refused cell is never lost, but each pass costs a probe or a call. The printed verdict carries `refused_unequal`. A controller error's message is kept only when the set retains diagnostic text (the default for replay cells). `sensitivity.json` is not sealed: a later `sensitivity` that flags a task blocks a resume. The toolchain's `--version` call runs outside the acceptance sandbox, and a set directory without `tasks/` (a chain's) records only the interpreter.

Other 1.9.0 behaviour: `sensitivity` grades each control again alone after the parallel pass and lists in `load_sensitive` the tasks whose grade moved; they leave the measure, and `run` refuses a set that still holds them (`load-sensitive-oracle`). A Claude CLI that reopens a session for a background task finished after its result (one more `init` with the same session id, after that task's notification) is one session: usage adds up, the cost is the last (cumulative) one and the receipt counts `continuations`; any other repeated `init` is still `ambiguous-session`. `native_runner --stream-copy FILE` (in `agent_command`: `--stream-copy {stream_copy}`) keeps the raw stream beside the cell, owner-only, for diagnosis; it holds the session's content. A snapshot's relative symbolic link whose target stays inside the snapshot is materialized as a copy; an absolute link, one leaving the snapshot or one with no target is still refused. A controller error records its type and innermost frame in the cell (`controller_error`) and on stderr, with its message when the set retains diagnostic text.

Acceptance execution uses the same configured `acceptance_sandbox` argv prefix and `acceptance_env` across replay cells,
lab collection and `admit --recheck`. An explicit environment (including `{}`) is exact apart from the controller's
`ACCEPT_REPORT`; omitted or null retains host inheritance for compatibility. Command prefixes are configured wrappers,
not proof of an operating-system sandbox. Cells identify their boundary as `host-unqualified` or
`wrapper-configured-unverified` and their environment as inherited or explicit. Configure containment before executing
untrusted candidates; no provider-specific mechanism is required by this policy. Existing frozen experiments keep their
original configuration and embedded acceptance adapter.

## What the report can say

| Claim | Gate |
|---|---|
| Less time | At least 25% less agent time per accepted change; fewer accepted changes raise that time, and whether the changes are the same is the next row |
| The same change | `same_change_reachable`: per task, the difference between the arms' pass rates on reachable behaviours (hidden tests red at base that some cell of the task passes), with a 95% t interval over tasks. `KILL` if the whole interval is below minus the declared margin (`compare.margin`, 3 points by default). `PROVEN` if `(mean + margin) / standard error` beats `proven_critical`: the 97.5% point of that statistic when the run's own cells are redrawn with a loss of the margin injected as whole failed attempts, so such a loss is called `PROVEN` about 2.5% of the time (in go-json simulations at 3 points: under 1% at two attempts per arm and 2.6–2.8% at about eight, where the plain t interval reached 5.6% and 3.4%; the report shows the plain rate as `t_false_proven`). A planned run can also fix a floor for the critical value from earlier attempts (`proven_critical(..., attempts=)`) and a frozen reach set (`reach=`). Otherwise `NOT-PROVEN`; under 8 tasks, `NO-INFORMATION`. A `KILL` here kills the thesis. The older point-estimate rule (tests that split a task's cells, -5 points) is kept only as `unseen_behaviour.superseded_verdict` |
| Durable | The change survives the next real change to the same code; requires `require_next` and `chain` |

Gates are fixed in code. If the oracle cannot reject planted defects, the verdict is `NO-INFORMATION`, never a pass.

## What one repository can answer

The savings settle fast: reasoning tokens, agent time and estimated cost per attempt need a few dozen commits. The same change does not. With the attempts each run had (about two per arm for Codex, three for Claude), a 3-point verdict needs hundreds of commits that reach new behaviour: about 190–360 with the noise measured for Codex on go-json, about 700 for Claude. A repository rarely has that many; go-json-experiment/json gave 41 out of 145 candidates. At that size `KILL` is a guard against a large loss (a loss spread across commits is caught four times in five only from about 10–12 points on), and `NOT-PROVEN` is the expected answer, not a failure. When a loss comes as rare attempts that fail outright, the t interval calls a 3-point loss `PROVEN` about twice as often as it should, which is why `PROVEN` uses a critical value simulated from the run. With it, two attempts per arm almost never prove; on go-json's 41 commits about eight per arm would prove equal arms about three times in four, if commits do not differ in effect. One verdict per executor.

Only some mined tasks reach new behaviour (41 of 62 on go-json). Given pilot results (`--results`), `feasibility` reports that share as `reach_share` and the tasks to mine as `tasks_to_mine_if_equal`; with `--sd` alone it assumes every task reaches.

## Choosing the margin

`compare.margin` in the set (a share, default 0.03, at most 0.2) is the loss `report` tests against; `feasibility` uses it too.
Declare it before any attempt, from the decision you face, never from the run that will be judged:

| Margin | What `PROVEN` means | Rough size at go-json's noise (Codex) |
|---|---|---|
| Break-even: reference acceptance × the saving share (about 0.10 at 36% acceptance and a 30% saving) | the lower effort does not lose what it saves | ~20 commits that reach new behaviour, 2 attempts per arm, ~US$25 |
| 0.05 | effectively the same change | ~40 such commits, 8 attempts per arm, ~US$165 |
| 0.03 | the same change within research precision | ~55–145 such commits, 8 attempts per arm: several repositories |

Sizes are per executor. Claude Opus 5.5 on the same go-json commits had about five times Codex's between-commit spread: break-even
at 2 attempts per arm needs about 40 commits for 80% power when the arms are equal
([result](../evidence/go-json-claude-20261107/RESULT-CLAUDE.md)).

Take the break-even inputs from a pilot or from published savings, never from the confirmatory attempts. Break-even is computed on acceptance while the verdict reads the reachable scale, so it is an approximation of the economic question, not the question itself. The sizes,
and those `feasibility` reports, are normal approximations: they ignore the calibrated critical value (stricter than 1.96) and the
8-task minimum, so read them as lower bounds. `report` reads the margin from the set each time it runs: keep the set unchanged
after the first attempt (hash it, as the pre-registrations here do). For a confirmatory run, freeze the reach set beforehand
(`reach=`); the calibration's error rates come from simulations that take the reach set as given. `report` writes `report.md`,
the verdict in plain words at the declared margin.

## Limits

Execution and acceptance timeouts must be positive and at most 2,147,483 seconds,
the portable subprocess wait range. The standalone CLI accepts whole minutes,
up to 35,791. Invalid limits are refused before execution.

A verdict holds for the specification form the set used (by default the commit message plus a contract of names its tests
pin) and is not a claim about other forms, such as written signatures or a skeleton. Filters that keep well-specified tasks
(`min_message`, the reach set, `sufficiency`) select tasks where the specification is already enough, which pulls a verdict
toward "equal". Commit messages often under-specify what their tests pin. A generated contract states names and strings, never behaviour, but tests can stay out of reach. Tests that fail in every cell carry no signal and leave the metric.

Durability is harder than it looks. In the repository where this was built, five instruments failed their own sensitivity gates, so durability was not testable there. Proving a binary outcome non-inferior at -5 points needs 235 to 1039 changes per arm, depending on the base rate. Treat `durable` as unproven unless `report` says otherwise.
